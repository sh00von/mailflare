## 1. Problem Statement & Strategic Foundation
Founders, indie hackers, and micro-agencies who manage multiple projects or domains face an expensive and clunky dilemma: Google Workspace and Microsoft 365 charge punitive per-user/month licensing ($7.20 to $14.40/user/month), multiplying costs across every side-project, while existing alternatives (Zoho, self-hosted Postfix/Mailcow, or email forwarding hacks) suffer from painful UI, deliverability nightmares, or broken reply threads.

## 2. Demand Evidence & Status Quo
- **Direct Founder Pain**: Paying $7.20/user/month per domain across dozens of early-stage domains before generating revenue.
- **The Duct-Tape Trap**: Free Gmail + Cloudflare routing + personal SMTP leaks sender headers, fails DMARC, and breaks inbound threading.
- **The Self-Host Trap**: Mailcow / Postfix requires continuous IP warmup, rDNS upkeep, and maintenance.

## 3. Target User & Narrowest Wedge
- **Target User**: Indie hackers, serial SaaS builders, and solo agency operators managing 3 to 15 domains.
- **Narrowest Wedge**: A unified webmail & custom domain dashboard with 1-click DNS record verification (SPF, DKIM, DMARC, MX) and managed outbound relay (Resend/Postmark) for flat $5–$29/mo domain-bundle pricing.

## 4. Strategic Pricing & Packaging (Reconciled)
- **Starter Plan**: $5/mo — 3 custom domains, 5 mailboxes, 10 GB storage, 50 sent emails/hour.
- **Pro Plan**: $15/mo — 10 custom domains, 25 mailboxes, 50 GB storage, 500 sent emails/hour.
- **Business Plan**: $29/mo — Unlimited custom domains, 100 mailboxes, 200 GB storage, high-volume sending.

## 6. Deep Technical Architecture & Section Audits

### Section 1: Architecture Review
```
                 +------------------------------------------------+
                 |              Public Internet                   |
                 +-----------------------+------------------------+
                                         |
                       +-----------------+-----------------+
                       | Port 4008 (HTTP)| Port 25 (SMTP)  |
                       v                 v                 v
                 +-----------+     +-----------+     +------------+
                 |  Next.js  |     | Inbound   |     | DNS-over-  |
                 |  Web App  |     | SMTP Svr  |     | HTTPS (DoH)|
                 +-----+-----+     +-----+-----+     +-----+------+
                       |                 |                 |
                       +--------+--------+                 |
                                |                          v
                                v                  (Cloudflare/Google)
                         +--------------+
                         | Neon PG Pool | (Users, Workspaces, Domains, Mailboxes)
                         +-------+------+
                                 |
                                 v
                         +--------------+
                         | Outbound     | ---> Resend / AWS SES Relay
                         | Relay Pool   |      (DKIM Signed, Rate-Limited)
                         +--------------+
```
- **Component Boundaries**: Next.js 15 App Router running webmail, auth, and API routes; standalone SMTP listener on port 25 with LRU hostname cache; Neon PostgreSQL with connection pooling.
- **Data Flow Tracing**:
  - *Happy Path*: Inbound mail connects to port 25 -> validates active domain from LRU cache -> parses MIME -> saves message to DB & attachments to storage -> emits realtime event.
  - *Nil / Missing Path*: Unrecognized domain or non-active status rejects immediately at `RCPT TO` with `550 5.1.1 Domain not found or pending verification`.
  - *Empty Path*: 0-byte or headers-only message rejected with `554 Empty message transaction`.
  - *Error Path*: DB pool exhaustion during write responds with `451 4.3.0 Temporary local error, try again later` (MTA will backoff and retry; zero message loss).

### Section 2: Error & Rescue Map
| Codepath | Failure Mode | Error Class | Rescued? | Action | User Experience |
|---|---|---|---|---|---|
| DoH Lookup | Timeout / DNS Down | `FetchTimeout` | Y | Return `unknown` status badge | "DNS check timed out, click to retry" |
| Outbound Relay | Rate Limit Exceeded | `RateLimitError` | Y | Reject send with HTTP 429 | "Hourly sending limit reached for Starter plan" |
| Port 25 Inbound | Oversized Message | `PayloadTooLarge` | Y | Early stream drop | MTA receives `552 Message exceeds maximum size` |
| Stripe Webhook | Webhook Signature Fail | `StripeError` | Y | Log & return HTTP 400 | Secure rejection, no state change |
| DB Pool Outage | Connection Timeout | `PoolConnectionError` | Y | Return 451 to SMTP / 503 to HTTP | Upstream retry, no unhandled crash |

### Section 3: Security & Threat Model
- **Domain Squatting & Traffic Interception (Mitigated)**: When a domain is registered, it remains `status: "pending"`. The system issues a unique verification record (`replyot-verification=<hex_token>`). Port 25 `RCPT TO` strictly requires `status: "active"`. Tenant A cannot intercept Tenant B's emails.
- **Port 25 Resource Exhaustion (Mitigated)**: `server/runtime/smtp.ts` uses an in-memory LRU cache (TTL 60s) for domain lookups, stopping dictionary attacks from saturating Neon PG connections. Inbound streams have an early 25MB cutoff to eliminate heap OOM crashes.
- **Anti-Replay Captcha**: Single-use nonce burning enforced in `src/lib/auth/captcha.ts` prevents replay attacks on registration and auth forms.

### Section 4: Data Flow & Interaction Edge Cases
- **Double Submit on Domain Add**: Unique index on `domains(hostname)` with graceful duplicate constraint catch; returns friendly "Domain already claimed" toast.
- **Stripe Downgrade Edge Case**: When a workspace downgrades from Business (10 domains) to Starter (3 domains), the oldest 3 domains stay active, while the remaining 7 are marked `status: "quota_paused"`. Inbound mail to paused domains receives `450 Mailbox quota exceeded`, giving the user a 7-day grace window to upgrade or re-activate priority domains.

### Section 5: Code Quality Review
- All database interactions use Drizzle ORM models.
- Dialect parity strictly preserved across SQLite, PostgreSQL, and MySQL per `AGENTS.md`.

### Section 6: Test Review
- **2am Friday Test**: Run automated script verifying registration -> domain add -> DoH check -> inbound port 25 delivery -> outbound relay dispatch -> Stripe checkout simulation.
- **Chaos Test**: Simulate 100 concurrent bad `RCPT TO` commands to verify LRU cache shields Neon PostgreSQL connection pool.

### Section 7: Performance Review
- Domain lookup latency at `RCPT TO` reduced from ~45ms (Neon roundtrip) to <1ms (in-memory LRU cache).
- DoH verification runs client-side on-demand with 30s debouncing, avoiding external rate limits.

### Section 8: Observability & Operational Runbooks
- Structured JSON logging on all SMTP transactions (`mail.received`, `mail.rejected`, `mail.relayed`).
- Ingestion of Resend bounce/complaint webhooks (`email.bounced`, `email.complained`) with automatic recipient suppression.

### Section 9: Deployment & Rollout Review
- **Hosting Reality**: Dedicated cloud VPS (Hetzner, DigitalOcean, OVH) with unblocked port 25 and configured PTR/rDNS record required for direct SMTP.
- PaaS platforms (Railway, Render, Fly.io) clearly documented as requiring edge webhook routing rather than raw port 25.

### Section 10: Long-Term Trajectory & Reversibility
- Reversibility: 4/5. Moving to external SMTP edge workers or dedicated MTA containers can be done seamlessly because domain and mailbox models are fully abstracted from transport.

### Section 11: Design & UX Review
- **Domain Health Dashboard**: Visual DNS status grid showing MX, SPF, DKIM, and DMARC with green checkmarks or 1-click copyable record values.
- **Keyboard Shortcuts**: Native inbox keybindings (`j`/`k`, `e`, `c`, `r`) for high-velocity email management.
